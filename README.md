# Glaux Website

*The home of a console from a 1993 that never existed.*

This repository contains the official website for [Glaux G1](https://github.com/Vulpix-Strix/glaux), an open-source fantasy console developed by Vulpix Strix.

Built with TanStack Start, the website brings together Glaux's documentation, development updates, tutorials, and everything surrounding the console.

The documentation is synchronized directly from the main Glaux repository, keeping the website and the console's built-in documentation consistent.

## Tech stack

- **TanStack Start** for routing, server-side rendering, and application infrastructure.
- **React and TypeScript** for the frontend.
- **Tailwind CSS** for styling.
- **Fumadocs** for documentation.
- **Cloudflare Workers** for deployment.
- **pnpm** for package management.

## Getting started

You'll need Node.js and pnpm installed.

Clone the repository and install dependencies:

```bash
git clone https://github.com/Vulpix-Strix/glaux-website.git
cd glaux-website
pnpm install
```

Start the development server:

```bash
pnpm dev
```

`pnpm dev` and `pnpm build` first synchronize the documentation from the public Glaux repository on GitHub. No token, authentication, or separate clone is required.

## Documentation

Glaux maintains its documentation alongside the console's source code.

Rather than maintaining a separate copy, this website imports the original Markdown files and adapts them for Fumadocs.

The integration preserves:

- The navigation order defined by Glaux.
- Heading anchors compatible with the built-in documentation viewer.
- Internal documentation links.
- Syntax highlighting for Luau and Rhai.
- Language availability and translation fallbacks.

### Versions

GitHub is the record of which versions are documented. `pnpm docs:sync` lists the releases of Glaux, keeps the published releases and prereleases, leaves drafts out, and adds the development documentation of `main`. Each one is resolved to its exact commit, and the `docs/` directory of that commit is written to `content/glaux/<version>/`, with its own pages, images, API catalog and manifest. A release tag is the name of its version; the documentation of `main` is `dev`. `dev` and `stable` are reserved and cannot name a release.

The list is written to `content/glaux/versions.json`, which the rest of the build reads. It is generated by every sync and never committed, so a new release needs no change to this repository. Checkouts are cached by commit in `.cache/glaux-source/`, so a release is downloaded once.

Every version has its own URLs, navigation, search index, images, Markdown and Open Graph cards:

- `/en/docs/<version>/<page>` is a page of one version, such as `/en/docs/v0.2.0/guide` or `/en/docs/dev/guide`.
- `/en/docs/stable/<page>` redirects to the latest stable release.
- `/en/docs/<page>`, the URLs from before versions, redirects to the recommended version: the latest release, else the latest prerelease, else `dev`.
- A redirect only happens when the target page exists. Unknown versions and pages are not found.

The sidebar has a version selector that keeps the page when the chosen version has it, by its Glaux id, and opens the start of that version otherwise. Search inside the manual covers the version being read; elsewhere it covers the recommended version. `llms.txt`, `llms-full.txt` and `sitemap.xml` describe the recommended version under its versioned URLs.

### Publishing

The site is built and deployed by Cloudflare Workers Builds. A build runs `pnpm build`, whose `prebuild` syncs every version, so a new release or a change to the docs of `main` only needs a new build. Cloudflare deploys only when the build succeeds, so a failing sync or build leaves the published site as it was.

[`website-deploy.yml`](https://github.com/Vulpix-Strix/glaux/blob/main/.github/workflows/website-deploy.yml) in the Glaux repository starts that build through a Workers Builds deploy hook when a release is published, edited, unpublished or deleted, and when `docs/` changes on `main`. Configuring it takes two steps outside this repository:

1. Create a deploy hook for the `main` branch in Cloudflare: Workers & Pages, `glaux-website`, Settings, Builds, Deploy Hooks.
2. Store its URL as the `WEBSITE_DEPLOY_HOOK` secret of the Glaux repository. Anyone with the URL can start a build, so it is never committed.

The sync reads releases from the GitHub API anonymously. A `GITHUB_TOKEN` build variable in Workers Builds is optional and only raises the rate limit; set a token without any scope if builds start failing with a 403 or 429 from GitHub.

Run `pnpm docs:check` after a sync to run Glaux's own documentation checks through `mise` on every version, each in a full checkout of its commit.

The generated documentation is not maintained manually in this repository. Changes to the original documentation should be made in [Vulpix-Strix/glaux](https://github.com/Vulpix-Strix/glaux).

## Development

Before submitting changes, run the available checks:

```bash
pnpm build
pnpm test
pnpm types:check
pnpm lint
```

`pnpm test` runs Vitest and includes `test/build-output.test.ts`, which reads `dist/`, so build first. `test/versioned-build.test.ts` builds a copy of the site from a simulated Glaux with two releases and `main`, and serves it with Wrangler; it reads the credits a build generates, so it is skipped until the site has been built once.

Documentation-related changes should preserve compatibility with Glaux's own documentation renderer.

Please avoid modifying generated documentation files directly.

## Interface translations

Site interface text lives in `messages/en.json` and `messages/es.json`, compiled by
[Paraglide JS](https://paraglidejs.com) into typed messages (`m.landing_hero_title()`) under
`src/paraglide/`, which is generated and ignored by git. Keys are lowercase snake_case, because
Paraglide lowercases message ids. Both catalogs must define the same keys and placeholders;
`pnpm test` checks it. `pnpm i18n:compile` regenerates the messages, and `pnpm types:check`
runs it first. Vitest compiles them through the Vite plugin.

The locale comes from the `/en` or `/es` path segment, which TanStack Router owns. Paraglide only
reads it (see `paraglide.config.ts`) and never rewrites URLs. Pass `{ locale }` as the second
argument of a message in code that has the route language at hand, such as `head()`. The manual
(`/en/docs`) and the editorial MDX articles keep their own i18n and are not part of these catalogs.

## Landing page

The landing is available at `/en` and `/es`; `/` redirects to English.
Documentation remains at `/en/docs`. Spanish landing links explicitly identify
English documentation. Landing styles are scoped separately from Fumadocs.

Hanken Grotesk and JetBrains Mono are self-hosted using Fontsource packages;
Pixel Code is reused from the Glaux intro project. Asset attribution and font
licenses are included in `public/ASSET-CREDITS.txt` and `public/fonts/`.

Four original PNGs are still required in `public/images/landing/`:
`signal-lost-gameplay.png` (320×240), `glaux-shell.png` (320×240),
`signal-lost-title.png` (320×240), and `master-palette.png` (16×16).
See `public/images/landing/README.md` for their exact content. The reference
HTML is visual guidance only; none of its embedded assets or scripts are used.
Until supplied, failed images show a localized message in reserved space.

News and Blog show their actual empty states until local articles are published.
Binary downloads remain unavailable; no release URLs are fabricated. The source repository and existing docs remain usable.

## Credits

The data of the Credits page (the people, the art, and the licenses of Glaux's crates and of this website's npm packages) is generated in `public/credits/`. The npm files are committed; the Glaux files are written by every build.

```bash
pnpm credits:sync
pnpm credits:check
```

Run `pnpm credits:sync` after changing a dependency and commit the result. CI runs `pnpm credits:check`. The npm packages are described in this repository only. `pnpm credits:glaux`, which `pnpm dev` and `pnpm build` run, reads Glaux's own credit files at the commit of the version the site shows and never edits them. See `credits/README.md` for how the data is built and how to add a missing license text.


## News and Blog

Localized listings live at `/en/news`, `/es/news`, `/en/blog` and `/es/blog`.
Articles are local MDX files with shared metadata, loading and rendering. Each
section has its own localized RSS feed at `/{lang}/{section}/rss.xml`.

Start with `/en/blog/devlog-template` or `/es/blog/devlog-template` in development.
The templates demonstrate all editorial components, including galleries,
comparisons, media, events and metrics. Draft articles and their exclusive
resources are excluded before production compilation and checked again in the
built output and Worker smoke tests.

See [the editorial authoring guide](content/editorial/README.md) for metadata,
publication, translations, assets and component examples. Never store draft
resources in `public/`.
