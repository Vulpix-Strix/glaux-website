# glaux-website

The official Glaux website uses TanStack Start/Router, React, Fumadocs and Tailwind CSS, with pnpm and Cloudflare Workers.

```bash
pnpm install --frozen-lockfile
pnpm dev
pnpm build
pnpm preview
pnpm test:worker
```

`dev` and `build` synchronize documentation first. Local development reads `../glaux/docs`; CI sets `GLAUX_DOCS_LOCKED=1` to use the pinned public commit. `pnpm preview` runs the built application in the Workers runtime. `pnpm exec wrangler dev` also starts the built Worker locally after a successful build.

## Architecture

```text
content/glaux/             generated documentation, ignored by Git
scripts/                   documentation maintenance commands
src/components/layouts/    current site and documentation layouts
src/components/docs/       documentation MDX components
src/lib/site.ts            public origin and site identity
src/lib/i18n.ts            published languages and language validation
src/lib/docs/              Fumadocs collection, URLs and i18n adapter
src/lib/glaux/             synchronization and Glaux compatibility contracts
src/routes/                TanStack file routes and HTTP handlers
src/styles/                current application styles
test/                      automated tests and fixtures
```

`src/routes/__root.tsx` owns the HTML shell and existing providers. The `/$lang` parent validates published languages and renders an Outlet; it does not impose documentation chrome. The layouts encapsulate the existing Fumadocs presentation. No landing design is implemented here.

`content/glaux/` is exclusively generated. The collection applies Glaux's Markdown plugins only to that content; other future content does not need its manifest or anchor/link conventions. Keep build-time MDX configuration out of request-time loaders.

For future editorial content, use `content/<section>/<language>/<slug>.md` (or `.mdx` when components are needed), versioned in this repository. Blog, Learn, Changelog and editorial pages each get a collection only when real content exists. Fumadocs can compile this content without requiring its documentation navigation. No CMS or database is needed.

Future routes are `/$lang/learn`, `/$lang/blog`, `/$lang/changelog`, `/$lang/games` and `/$lang/play`, with `/$lang/<section>/$slug` for individual content where appropriate. They are not registered until implemented. Play can mount an interactive application without inheriting DocsLayout. Only existing destinations should appear in navigation.

English is the only published language. To enable Spanish later, add `es` to `languages` in `src/lib/i18n.ts`, add UI translations/display name in `src/lib/docs/i18n.ts`, add the search locale mapping and the corresponding documentation patterns in `wrangler.jsonc`, and supply real translated content. Keep the default English language consistent with Glaux's English fallback. The sync already reports missing translations and rejects translations without originals; do not copy English pages into a Spanish tree.

`src/routeTree.gen.ts` is generated by TanStack Router and should be versioned with route changes, never edited by hand. Content output, `.source`, `.tanstack`, `.wrangler`, build output and source caches are ignored. Scripts and fixtures remain alongside the small existing test suite; there are no empty feature directories.

## Cloudflare Workers

The project uses only `@cloudflare/vite-plugin`, the integration documented by TanStack Start and Cloudflare. Nitro has been removed. `wrangler.jsonc` declares the entry, Worker name and compatibility date. With compatibility dates from 2026-08-04 onward Node.js compatibility is enabled by default, so no redundant Node compatibility flags are set.

The build preserves SSR and prerendering. `src/server.ts` is a small Workers entry around TanStack's standard handler: documentation requests reach the Worker first, HTML can use the prerendered ASSETS binding, and Markdown negotiation stays with Start. Root requests also reach Start so `/` keeps its HTTP redirect to `/en`. Asset HTML handling drops trailing slashes, preserving existing documentation URLs. The generated asset configuration needs no separate hosting integration.

`pnpm test:worker` starts Wrangler locally against `dist/server/wrangler.json`, waits for readiness, tests real HTTP responses and stops the process. CI runs it after the build. It includes SSR on `/en`, which is not prerendered, static docs with `Vary: Accept`, assets, search, Markdown negotiation, LLM output, WebP OG generation and 404s.

Git, source checkouts and Markdown compilation are build-time concerns; the deployed Worker uses bundled content.

`pnpm deploy` builds and manually deploys after the operator has configured their Cloudflare account. No deployment workflow or domain configuration is included.

## Glaux documentation

The manual lives in the Glaux repository (`docs/`). Glaux owns it; this site only reads it, never edits or copies it by hand. `pnpm docs:sync` turns it into `content/glaux/` (git-ignored, regenerated by `predev` and `prebuild`) and checks it.

### Where the documentation comes from

| Command | Source |
|---|---|
| `pnpm docs:sync` | The sibling checkout `../glaux/docs`, or `--source <dir>` / `GLAUX_DOCS_DIR`. For development. It warns when that checkout is not at the pinned commit. |
| `pnpm docs:sync --locked` (or `GLAUX_DOCS_LOCKED=1`) | The commit pinned in `glaux-docs.lock`, fetched with Git into `.cache/glaux-source/` (only `docs/`). Used by CI and production; ignores any local checkout and never reads a branch. |

Nothing is fetched at run time. Both modes fail, listing every problem, when the source or the commit is unavailable, a page listed in `ids.lock` is missing, a translation has no English original, or a `glaux://` link or `#fragment` does not resolve. `manifest.json` records which commit the output came from.

`glaux-docs.lock` holds the repository and the full commit hash. Other useful commands: `pnpm docs:check` runs Glaux's own `mise run docs-check` (it includes Rust tests, so it needs Glaux's toolchain), `pnpm test`, `pnpm types:check`, `pnpm lint`.

### Updating the pinned revision

1. Merge the documentation change in the Glaux repository.
2. Here, run `pnpm docs:pin` (head of Glaux's default branch), `pnpm docs:pin <branch|tag|hash>`, or `pnpm docs:pin --local` (the commit of `../glaux`, which must be pushed). It fetches that commit to prove it exists and rewrites `glaux-docs.lock`.
3. Run `pnpm docs:sync --locked && pnpm test`, then commit `glaux-docs.lock` in a pull request. CI repeats the checks on the pinned commit and, because the lock changed, runs Glaux's documentation validator on it.

### Conventions

- **Page order** is Glaux's own, from `workspace/docs/nav.rs`: sections `guide` then `api`, then others by name; inside a section the pages an `index` page links to come in link order, and the rest by id. The site reads the same index pages, so there is no second list (`src/lib/glaux/order.ts` is a port of that function; its tests mirror Glaux's). The result becomes a `meta.json` per folder in `content/glaux/`.
- **Heading anchors** are Glaux's (`glaux_docs::anchor`), not `github-slugger`'s: `remark-glaux-anchors` sets each heading's `id`. The first heading with an anchor keeps it, repeats get `-2`, `-3`…. A link to the level 1 heading (the page title) opens the page. `src/lib/glaux/anchor.ts` is tested against the same cases as the Rust function.
- **Rhai** is highlighted with the grammar of [rhaiscript/vscode-rhai](https://github.com/rhaiscript/vscode-rhai) (MPL-2.0, vendored unchanged in `src/lib/glaux/grammars/`); Luau is bundled with Shiki.
- **Languages**: pages are `docs/<lang>/<id>.md`; ids are the same in every language. Only English exists today. When `docs/es/` appears the sync step lists untranslated pages (`manifest.missing`), rejects translations without an English page, orders pages through the language's own index (falling back to English's), and resolves `glaux://` links to the English page when a translation is missing. Spanish remains unpublished until real translations and interface strings are ready; unpublished language routes return 404.

### CI

`.github/workflows/ci.yml` installs with the frozen lockfile, downloads the pinned Glaux commit anonymously, syncs, tests, typechecks, lints and builds. `glaux-docs-check.yml` anonymously fetches the complete pinned revision and runs Glaux's documentation validator when the lock changes.

Remote access uses public HTTPS without credentials or prompts. While `cuervolu/glaux` remains private, fresh locked syncs and CI fail explicitly. There is no automatic fallback to local or vendored documentation. An existing clean cache at the pinned commit may be reused; local checkout workflows remain available for development. Making Glaux public is a separate operation outside this repository.
